# Как устроено и как предлагать изменения

## Устройство

| файл | что делает |
|---|---|
| `catcher.py` | читает уведомления из `dbus-monitor`, разбирает (чат, отправитель, сайт, почта, аватар), пишет в SQLite; миграции схемы |
| `schema.sql` | схема базы |
| `rules.py` | источники, правила «как в почте», профили, настройки, действия при записи |
| `serve.py` | локальный HTTP-сервер: страницы и API; фоновые задачи |
| `collect.py` | сбор + сервер одним процессом (так работает сервис) |
| `widget.py` / `widget.html` | окно виджета (GTK + WebKit) и его страница |
| `settings.html` | окно настроек |
| `i18n.js` / `i18n.py` | перевод страниц / сообщений сервера (русский ключ → английский) |
| `actions.py` | звук и пересылка в Telegram |
| `mail.py` | почта напрямую из ящиков (IMAP): ящики, проверка, фоновый опрос |
| `rag.py` | необязательный умный поиск через Ollama |
| `backup.py`, `report.py`, `stats.py`, `ingest.py`, `diag.py`, `avatars.py` | копии, недельный отчёт, статистика, приём событий, самодиагностика, аватары |
| `paths.py`, `version.py` | где лежат данные (XDG), имя и версия программы |
| `install.sh`, `uninstall.sh`, `packaging/`, `hooks/` | установка, юниты systemd, хук терминала |
| `wincatcher.py`, `winwidget.py`, `messhub_win.py` | Windows 10/11: чтение уведомлений (UserNotificationListener), окно на WebView2, всё одним процессом `messhub.exe` |
| `tools/build.py`, `tools/build_windows.py` | пакеты: `.deb`, `.rpm`, `.tar.gz`; на Windows — exe → zip, `.bat`, `.msi` (CI: `.github/workflows/packages.yml`) |
| `packaging/linux`, `packaging/windows`, `packaging/icons` | команда `messhub` и ярлык, установщики для Windows, значок (`tools/make_icons.py`) |
| `tools/demo_data.py`, `tools/screenshots.py` | вымышленные данные и скриншоты для README |
| `tools/check_public.py`, `tools/i18n_check.py` | нет ли личного в коммите; у всех строк есть перевод |

## Ветки и pull request'ы

- `main` — выпущенные версии, в неё пушат только владельцы. `contrib` — сюда принимаются PR.
- Сделай форк, ветку от `contrib` (`fix/…`, `feat/…`), открой PR **в `contrib`**. PR в `main` не принимаются.
- Перед коммитом — `python3 tools/check_public.py --staged`: не даст закоммитить базу, токен
  или личный путь (удобно повесить в свой `.git/hooks/pre-commit`).
- CI проверяет тесты (Python 3.9, 3.12, 3.13 и Windows), переводы и то, что в PR нет личного;
  изменения для Windows и пакетов ещё и собираются (`packages.yml`: exe, zip, msi, bat, deb, rpm).
- Номер версии в коммитах не трогай: он равен номеру коммита (`python3 version.py`).

## Запуск без установки

```bash
python3 tools/demo_data.py --home /tmp/messhub-demo          # вымышленные данные
MESSHUB_HOME=/tmp/messhub-demo python3 serve.py --db /tmp/messhub-demo/share/messages.db --port 8799
python3 widget.py --url http://127.0.0.1:8799/widget --state /tmp/messhub-demo/w.json   # окно к тестовому серверу
python3 collect.py                                            # или настоящий сбор + страница (Ctrl+C — стоп)
python3 tools/screenshots.py                                  # переснять картинки README (нужен Xvfb)
```

## Правила игры

- **Приватность прежде всего.** Источник данных — только уведомления, которые система и так
  показывает. Наружу — только то, что пользователь включил сам. Никакой телеметрии.
- **Только стандартная библиотека Python** (и `gi` для окна). Новая зависимость — только если без
  неё никак, и необязательной.
- **Схема базы меняется только с миграцией** в `catcher.migrate()` / `migrate_after()` и тестом в
  `tests/test_migrate.py`.
- **Строки интерфейса** пишутся по-русски через `t('…')` и получают перевод в `i18n.js`
  (сообщения сервера — `L("…", "…")` из `i18n.py`).
- **Тесты** — `python3 -m unittest discover -s tests -t tests`; сеть и рабочий стол в тестах
  не нужны. Перед PR ещё `python3 tools/i18n_check.py` и `python3 tools/check_public.py --staged`.
- **Никаких настоящих уведомлений** в коде, тестах, скриншотах, issues и PR — только выдуманные
  имена и тексты. Что можно публиковать, а что нет, — ниже, «Что можно публиковать».
- **Каждое заметное изменение** — строкой в раздел «Не выпущено» в `CHANGELOG.md`; выпуск версии —
  номер в `version.py` + запись в `CHANGELOG.md` + тег `vX.Y.Z`.

## Что можно публиковать

Программа работает с личными уведомлениями людей, поэтому в репозиторий, issues и PR — только выдуманное.

- **Можно:** код, тесты, документация; скриншоты — только из `tools/screenshots.py` (вымышленные данные
  `tools/demo_data.py`, скрипт сам прячет пути); примеры — придуманные имена, адреса `@example.com`,
  токены вида `demo-token-not-real`.
- **Нельзя никогда:** базы `*.db` и копии, логи, `telegram-forward.json`, `ingest.json`, `mail.json`,
  `widget-state.json`; тексты, имена и чаты из настоящих уведомлений (даже одну строку); скриншоты
  живой доски; пути `/home/<имя>/…`; настоящие токены, пароли, ключи.
- **Как проверить:** `python3 tools/check_public.py --staged` перед коммитом, `--commits` — ещё и сообщения
  коммитов. Личный стоп-лист (своё имя пользователя, рабочие названия) — файл `.public-deny` в корне,
  по слову на строку; он в `.gitignore`.
- Отлаживай на демо-данных: `python3 tools/demo_data.py --home /tmp/demo`. Баг на настоящем
  уведомлении — воспроизведи на выдуманном тексте той же формы и клади в тест уже его.

## Номер версии

Версия — `1.0.<номер коммита, считая с нуля>`: каждый коммит +1. Руками номер не меняют — его считает
`version.py` (`python3 version.py`), а в пакеты вписывает сборка. Выпуск — тег `v<номер>` на `main`.
